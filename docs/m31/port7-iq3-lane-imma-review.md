# Port7: независимый arithmetic review IQ3 lane IMMA

Проверено source-only по actual stock AVX2 `ggml_vec_dot_iq3_xxs_q8_K` (vendor quants.c SHA777d0a4c), старому `tools/m31/gpu_cpu_quants.cu` SHA5c378898 и исходной схеме нового stage1/stage2 от dense owner. Затем отдельно прочитан записанный `port7_iq3_lane_imma.cu`: A fragment regs0/1/2/3, masked B, D mapping, per-sub scales и scratch offsets соответствуют схеме. Whole-warp K tail и полные8-lane группы finish при row tail безопасны. Runtime/kernel execution или модель этим review не проверены. Engine/vendor не менялись, новых сборок и GPU запусков не выполнялось.

Для каждого K256 CPU держит8 I32 lane. Lane L собирает positions4L..4L+3 каждого из8 sub32, затем умножает каждый partial на соответствующий row/sub odd scale1..31 и суммирует в I32. AVX2 разделяет even/odd sub32 на sumi1/sumi2, но последующее I32 сложение эквивалентно обычному ascending sum: overflow отсутствует. После K256: `d=RN(F32(F16wd)*Q8K.d)`, `acc[L]=fmaf(d,float(isum[L]),acc[L])`. Порядок K256 неизменный. После всех Kblocks CPU reduction — upper+lower, пары0+2/1+3, затем0+1; последним `*.25f`.

Сохранение8 независимых CPU lanes до FMA — существенное условие. Нельзя сначала суммировать lanes/subblocks в F32, применять .25 к wd до FMA, объединять Kblocks в один IMMA integer accumulator или вычислять F32 matrix dot и потом восстанавливать дерево. Q8K.d может быть отрицательным; брать abs нельзя. F16→F32 точен для конечных half, а отдельный `__fmul_rn` воспроизводит scalar d перед FMA. Для проверок subnormal d нужны `--ftz=false` и согласованный CPU FP environment; обычные model inputs не доказывают этот крайний случай.

Все magnitudes таблицы iq3xxs_grid≤62; |q8|≤128 даёт консервативные границы: unsigned×signed adjacent pair≤15872, поэтому AVX2 MADDUBS не насыщается; четыре positions одного sub/lane≤31744; умноженный на31 и просуммированный по8 sub32 lane≤7,872,512. Это меньше INT32 и2^23; финальное I32→F32 для одного K256 lane точное. В valid finite activation domain Q8K ref использует -127/max и не создаёт -128; там фактическая граница ещё ниже. Если raw q8=-128 подать вручную, CPU PSIGNB wrap `neg(-128)=-128` отличается от scalar GPU signedweight*q8. Старый GPU short kernel уже использует второй вариант. Поэтому raw-128 надо либо явно исключить/assert, либо отдельно реализовать stock wrap; нельзя молча объявить proof на произвольных int8.

Для stage1 подходит m16n8k32: A содержит signed IQ3 weight values, B[k,col] содержит Q8K.qs[k] лишь при floor(k/4)==col, остальные0. Тогда output col — ровно CPU lane из4 products. Row/sub scale умножается **после** IMMA в I32: он различается по row/sub и в A int8 не помещается (62×31>127). Масштабированные8 sub32 суммируются в I32, scratch layout[row,K256block,CPUlane]. Каждый sub MMA accumulator должен начинаться с0 до scaling, иначе разные sub scales применятся неверно.

Output fragment mapping подтвержден по [NVIDIA PTX9.7.16.5.10](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#warp-level-matrix-fragment-mma-16832): thread warp lane T, register i0..3 соответствует row=T/4+8*(i/2), col=2*(T%4)+i%2. Input B и A имеют разные fragment layouts; маску B надо строить по логическому k/col, а не путать output reg i с CPU lane. Все32 warp threads обязаны выполнять MMA; хвост rows<16 должен занулять A без early-return части warp и не читать отсутствующие weights/scales.

Изолированный host helper `tools/m31/port7_iq3_lane_reference.hpp` использует исходные ggml-common types/tables. Он возвращает unscaled[8sub,8lane], scaled и sum[8lane]; запрещает raw-128, даёт fragment_position() и FMA/reduction finish(). Это отдельный HOST C++ TU, не CUDA include; --fast-math запрещён. Пока helper не компилировался/не запускался.

Предлагаемая диагностика до общего F32 результата: сравнить каждый stage1 scratch I32 с host per-lane reference. Сначала реальные weight rows с разными grid/sign/scale, Q8K basis vectors (все0 кроме одной позиции±1/±127) для всех256 positions: так видны ошибки sub32, lane4positions, знака и D fragment. Затем dense/random Q8K[-127,127], все16 rows и row tails1/7/15/17, K256/512/1536/6144, реальные и экстремальные конечные scales. После I32 proof отдельно сверять F32 stage2 с8-lane CPU и старым GPU short; лишь затем компонент FFN и модель. Unscaled/sub-local debug scratch стоит оставлять opt-in, он не нужен final performance kernel.

Host harness `port7_iq3_lane_check.cpp` затем прочитан отдельно: source review PASS. План1024 basis cases +35 raw tail cases +684 matrix cases (57layers×2roles×2experts×3L3activationrows). Raw I32 сравниваются все, реальные I32 —7 выбранных rows; F32 сравниваются все запрошенные rows с CPU nrc1 и старым GPU. Один borrowed stream сохраняет порядок quant/stage1/stage2/copies. Timing full3072rows/scratch наlayer10 согласованы; cold capacity rotation честно не называется measuredL2miss. Все model-layer inputs в этом компоненте повторно используют реальные L3 input rows, не actual layer activations. Runtime результата на момент review ещё нет.
