## Путь добавления модели

GLM начинался коммитом `e889e759`: отдельные `tools/glm/glm_dense.{hpp,cpp}`,
драйвер `glm_generate.cpp`, включаемый CMake-фрагмент. Attention, router, dense/shared
FFN строятся на ggml; routed experts передаются в общий `tools/ds4/ds4_moe`.
Затем `45ea8da7` добавил индексер, `174da568` — протокол сервера и Python shim.
Именно этот порядок подходит M3.1. Qwen `src/core/qwen35.cpp` теснее связан с
фиксированной геометрией основного движка и гибридным attention; это менее удобная основа.

Новый opt-in модуль: `tools/m31`. Первое плечо корректности: собственные графы
attention/router/dense/shared FFN и CPU ggml `mul_mat_id` для routed experts,
без перекванта и приближений. Это подготовка к тирингу, не скоростной движок M2.
Затем заменить вычислитель routed experts общей RAM-ареной/VRAM-кешем после
расширения контрактов активации и размеров. Сервер — общий `serve` и M31 shim.

## Контракт архитектуры

- D=6144, 60 слоёв, Q heads=64, KV heads=4, head dim=128, rotary dim=64,
  theta=1e7, RMS epsilon=1e-6, vocab=200064.
- FFN слоёв 0–2 плотные (12288); 3–59: 128 экспертов, top-4, expert FF=3072,
  общий эксперт FF=3072. Плотный FFN не означает плотное attention.
- MSA на всех 60 слоях: 4 query index heads по 128, один index key head;
  score — dot product в F32, causal mask ДО max-pool, max по блоку 128,
  top-16 блоков отдельно для каждой GQA-группы, локальный блок с bias=1e30.
  При длине >2048 начинает исключать блоки. Нужны проверки 2048/2049 и 3000,
  а также границ 127/128/129 и split-prefill.
- Decode: gather выбранных KV и один сгруппированный flash-attention. Prefill:
  блоковая маска + FA, ограничение размеров промежуточных тензоров <2^31.
  Начальное ограничение — одна append-only последовательность, F16 KV/index KV.
- Router: sigmoid; bias используется только для ВЫБОРА. Веса выбранных экспертов
  берутся из unbiased probabilities, нормируются с clamp суммы >=6.103515625e-5,
  затем умножаются на 2. Никаких cache-aware route biases для M1/M2 quality gate.
- `swigluoai`: `min(g,7)/(1+exp(-1.702*min(g,7))) * (clamp(u,-7,7)+1)`.
  Обычный clamped SwiGLU Xolotl не эквивалентен: отличаются alpha и `+1`.
- Gemma `1+w` уже внесено конвертером в GGUF norm weights. Вторично не добавлять.
- NFC требуется до BPE. На M1 подавать одинаковые token IDs обоим движкам;
  токенизатор отдельно сверять с llama.cpp/HF на decomposed Unicode и chat template.
- В HF репозитории text `modeling*.py` не опубликован (есть configuration и
  мультимодальные processors); источник формул этого этапа — зафиксированный PR.
  Маленький `dspark/config.json` сохранён отдельно: 5 плотных draft layers,
  FF=12288, block=7, noise ID=200058, sliding window=4096, markov rank=256,
  target IDs=[3,17,31,45,59]. Перед M3 проверить семантику input/output taps
  и нумерацию в GGUF/dflash (не переносить V4.1 block5/window128 и три MoE слоя).
  Реальный Q8_0 draft уже проинспектирован: GGUF хранит target_layers=
  [4,18,32,46,60], то есть сдвиг +1 относительно HF; это критичный контракт taps.
  У него 62 тензора, payload 2081138692 байт; у mmproj — 524 тензора,
  payload 1735264256 байт (BF16/F32). Заголовки сохранены в `refs/aux-gguf.json`.

## Что переиспользовать и что изменить

| Узел | Решение |
|---|---|
| GGUF split/mmap, типы | Существующий `GgufModel`, проверка полной tensor map |
| IQ3_XXS, IQ4_XS, NVFP4 | Уже есть CPU/CUDA kernels, ggml fallback и NVFP4 scale-tail; новый квант не нужен |
| MSA | Собственный композит по minimax-m3.cpp, затем fused max/top-k/gather по профилю |
| V4.1 lightning indexer | Инфраструктура замера/выгрузки полезна; формула другая: его ReLU/сумма голов и compressed KV НЕ являются MSA |
| `STRATA_INDEXER_NVIS` | Идея короткого visibility input; прямое применение здесь некорректно |
| `GGML_CUDA_MXFP4_WMMA` | Может быть полезен другим частям, но index projections этого GGUF — F32, не MXFP4 |
| RAM arena/VRAM cache | Общий Ds4MoeTier, переменный размер blob по слоям, elastic cache после prefill |
| CPU scratch | 6144/Q8_K=7008 байт, 3072/Q8_K=3504, FF=3072; текущие пределы 5840/2628/2304 недостаточны |
| NVFP4 scales | Ds4GgufBlobs сейчас не читает `.scale`, а down stride включает tail — нельзя использовать без исправления |
| Активация | Новый opt-in OAI режим во всех CPU/CUDA/grouped/MMQ путях; default DS/Qwen не менять |
| Prefill | Layer-major chunk, группировка маршрутов по экспертам; GPU MMQ для каждого типа и масштабов |
| DSpark | Приёмка/rollback/verify из V4.1, но архитектуру драфта брать из dflash.cpp, не Ds41DSpark |
| Vision | Сначала mtmd encoder adapter и embedding input вместо text embedding, затем видео/кадры |

В GLM-загрузчике есть автоматический BF16→Q8_0 и optional Q6_K→Q4_K.
Не переносить их в M1: загружаем исходные типы. Нельзя подменять MSA полным
attention на длинных промптах или отключать индексер первых трёх слоёв.

## Реальные байты и предварительный бюджет

- Routed tensors: 163754016768 байт = 152.51 GiB, 7296 экспертов.
- Типы routed tensors: 156 IQ3_XXS, 12 IQ4_XS, 3 NVFP4 (всего 171 =57×3).
- NVFP4 только down слоёв 52, 58, 59; каждому соответствует F32 `.scale[128]`.
- Остальные веса: 11688118272 байт =10.89 GiB, включая token embedding.
  Резидентные GPU-веса меньше, если embedding lookup на CPU; точный runtime overhead ещё не измерен.
- F16 main KV: 120 KiB/токен на 60 слоях. F16 index KV: ещё 15 KiB/токен.
  Вместе 4.21875/8.4375/16.875 GiB на 32K/64K/128K токенов, без workspace.
- Полная RAM-арена помещается в 624 ГБ. Статический GPU-кеш на 32 ГБ держит
  лишь часть экспертов. При среднем blob ~21.4 MiB поток всех 228 активных
  экспертов/токен через PCIe потребовал бы ~4.8 GiB/токен. Поэтому CPU-плечо,
  hit rate и группировка prefill принципиальны. Это оценка байтов, не замер t/s.

## Нужна ли модификация модели

Для корректности — **нет**. Читаем тот же UD-IQ3_S и исходные `.scale` напрямую.
Первый этап не переквантывает ни dense, ни routed tensors.

Рейтинг наподобие `rank-xq3k.bin` — полезный отдельный профиль размещения, а не
модификация весов. Он ускорит начальный прогрев кеша и даст более горячим экспертам
VRAM; качество не меняется, если маршрутизация точная и все misses вычисляются.
Нужен собственный M31-корпус, измерение hit rate на held-out запросах и полное
покрытие 57×128. Рейтинг V4.1 неприменим.

Перепаковка `[gate|up|down|scales]` в RAM нужна внутреннему контракту арены;
записывать новую модель на диск необязательно. Она экономит faults/сборку blob,
позволяет pinned DMA и prefetch. Опциональный disk sidecar позднее может сократить
время старта, но обязан сохранять деквантизованные значения и fingerprint GGUF.

Свой квант — только отдельный последующий эксперимент после M1/M2. NVFP4 down
имеется лишь у трёх слоёв; пока нет профиля, переквант всего checkpoint не обоснован.
Потенциальная польза: меньше bandwidth и больше кеша; цена — новая ошибка и потеря
точного эталона. Смена квантования требует повторной проверки качества.

## Приёмка и порядок

1. M1: tensor/geometry guard, собственные графы, raw-F32 logits и per-layer taps;
   отдельный oracle на PR 31192. Двадцать фиксированных RU/EN/code/math prompts,
   64–3000 токенов, одинаковые ID, контроль batch/decode и MSA top-k. Проверять
   top-1>=99%, mean KL значительно меньше 1e-3, finite values и max KL;
   при ошибке первый расходящийся слой, затем attention/router/FFN.
2. M2: OAI kernels и scale-tail, RAM arena, GPU-0 cache, батч, protocol/API;
   `~/om_bench.py` 4K/16K/32K decode и 4K/32K prefill, GSM8K 100, tools 23.
   Сравнение с лучшим ОДНОКАРТОЧНЫМ плечом REPORT.md, а не со старыми 15/400.
   Если преимущество отсутствует или мало, остановиться после отчёта M2.
3. M3: MiniMax DSpark dflash, per-layer taps из metadata драфта, точная greedy verify,
   acceptance, accepted tokens/step, TTFT и t/s. V4.1 DSpark не plug-and-play.
4. M4: vision BF16 mmproj, mtmd parity для одной картинки, затем video frames;
   особые image/video ID, patch-merge и temporal_patch_size=2 учитывать явно.

Инженерная оценка (не обещание): M1 1–2 рабочих дня, M2 2–4, M3 1–2,
M4 2–3. Главная неопределённость — скорость точного MSA и OAI expert paths на
одной 5090, а не загрузка GGUF. Однокарточные 128K существенно уменьшают кеш.

## Эксплуатационные ограничения

Пока `systemctl is-active -q codex-m31-ref`: только чтение/проектирование/запись,
без сборки, CPU-inference, конвертаций и GPU. В этот период нет новых t/s.
Долгое — transient systemd unit `-p User=nekto`, лог в `/mnt/ai/logs/m31-port`.
Карты только `aictl`, под `flock -w 86400 /mnt/ai/logs/.xolotl-card.lock`;
только GPU 0. Cleanup trap должен дождаться возврата `aictl up`, затем `aictl down`.
Системный preset создаётся с backup и rollback-командой, в конце этапа снимается.
Продовые up*/hxq3k/launcher не меняются. Только локальные коммиты этой ветки,
без push/PR и attribution. Итог референса ещё не появился — использовать после
завершения юнита, не пытаться угадать его лучшие числа.
