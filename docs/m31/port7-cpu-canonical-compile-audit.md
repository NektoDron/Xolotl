# Port7: read-only CPU compile/assembly audit canonical/v2 vs V8

Проверка по frozen receipts, CMakeCache, compile_commands, object/archive contents и individual-symbol objdump. Сборки, runtime edits, perf и benchmarks не запускались. Артефакты `/mnt/ai/logs/m31-port/port7-cpu-compile-audit-v1/receipt.json` и три пары fused-compute asm; полные GPU ELF не хешировались заново.

GCC/G++ одинаковые14.3.0. CPU quants и pool собраны с -O3 -DNDEBUG -march=native; Engine -O3 -DNDEBUG -std=c++20 без -march/-ffast-math/-frounding-math, одинаково V8/V11/canonical после исключения include/source/output paths. CMake GGML_NATIVE=ON, CPU_REPACK=ON; AVX/AVX2/AVX512/FMA option flagsOFF в обоих, но это не выключает ISA, которую включает -march=native. Никакого найденного CPU compileflag regress нет.

Сильнее flags: весь arch/x86/quants.c.o **byte-identical**,68512bytes, SHAb77859ca235e92fc731f1b99ec4bd5fc3cb6b2c1456acf0fd32a08404a3f3276. Generic CPU quants.c.o тоже одинаков. Object members подтверждены внутри соответствующих libggml-cpu.a; старый archive hash48f6ca9d… совпадает с V8 frozen receipt. В pool object bytes функций ggml_barrier, ggml_graph_compute_secondary_thread и ggml_threadpool_new_impl совпадают побитно. Whole pool object/archive SHA различаются, поэтому их нельзя называть полностью одинаковыми; это не отличие проверенных hot functions.

Callback CpuFusedDecode::compute вырос1512→1557bytes (+45), но **stack frame неизменно0x48=72bytes** и набор rsp-relative offsets совпадает. Nonzero paired_quant ведёт отдельным tailjump в compute_paired после восстановления frame; local[256] не inlined в default callback. Есть31 вместо30 stack-reference instructions при подсчёте всех callback paths, это не доказательство нового hot-loop spill. Canonical и V11 callback object bytes полностью совпадают. Гипотеза дополнительного1KiB stack на mode0 исключена; branch/code layout V8 и нового callback всё ещё различается, причинного TPS вывода по нему нет.

Fresh paired logs подтверждают в обоих arms: threads80, persistent1, poll50, strict0, affinity_cpus0, fusedCPU1, chain1, async_reads1, cached_gpu0; одинаков также footer CPU/shared overlap1. Это runtime metadata, не предположение по наличию environment key. Новые opt-in режимы pair/rank/cache не объявляются включёнными из-за самого включения header в бинарник.

Во время canonical control: та же policy, Tctl68.625°C; raw CPU MHz max≈3.698GHz с boost, median192logical CPUs1.5GHz. FreshV8-underload snapshot пропущен, matched power/APERF counters отсутствуют. Powercap node имеет enabled0 и не даёт основания делать вывод о BIOS package power limit или throttling. Политики/питание не менялись.
